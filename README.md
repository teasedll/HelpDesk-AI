# HelpDesk AI

Веб-сервис университетской техподдержки: регистрация пользователей, заявки, статусы, комментарии, история изменений и прототип ML-классификации обращений.

## Технологии
Python, Flask, PostgreSQL, HTML/CSS, scikit-learn (TF-IDF + Logistic Regression).

## Быстрый старт (macOS / Linux)

1. Установите Python 3.10+ и PostgreSQL.
2. Откройте терминал в папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

3. В `.env` укажите свою строку `DATABASE_URL` и случайный `SECRET_KEY`. Пример генерации ключа: `python3 -c "import secrets; print(secrets.token_hex(32))"`.
4. Если БД уже создана, **не нужно удалять таблицы**. Схема использует `IF NOT EXISTS` и не меняет существующие структуры. Выполните:

```bash
psql -d helpdesk_ai -f database/schema.sql
psql -d helpdesk_ai -f database/seed.sql
```

Если БД ещё нет, сначала `createdb helpdesk_ai`.

5. Запустите:

```bash
python run.py
```

Откройте http://127.0.0.1:8000.

### Контакты общежитий

Выбор общежития сохраняется в браузере и подставляется на странице контактов и в форме заявки. Чтобы показать подтверждённые телефоны, задайте в `.env` переменную `HELPDESK_DORM_CONTACTS` как JSON, например `'{"4":{"commandant":"","duty":""}}`. Ключ — номер общежития, пустая строка показывает «Телефон уточняется». Для кнопки связи с разработчиками укажите адрес в `DEVELOPER_EMAIL`.

Номер общежития, комната и контакт сохраняются в тексте заявки в текущей схеме PostgreSQL.

### Вход для демонстрации

Чтобы добавить учебные аккаунты и заявки, выполни `database/test_database/test_data.sql` после `schema.sql` и `seed.sql` в локальной тестовой базе, указанной в `DATABASE_URL`. Если учебные аккаунты уже есть, можно сразу войти.

| Роль | Электронная почта |
| --- | --- |
| Студент | `hdai-lab-v1-1@example.test` |
| Сотрудник поддержки | `hdai-lab-v1-12@example.test` |

Пароль обоих учебных аккаунтов — `HelpDesk-Lab-2026!`. Загрузка демонстрационных данных выполняется отдельно от обычной настройки проекта.

## Что реализовано
- Регистрация и вход; пароли хешируются Werkzeug.
- Роли `USER`, `SUPPORT`, `ADMIN`; публичная регистрация всегда создаёт `USER`.
- Пользователь видит только свои заявки; сотрудники поддержки видят все.
- Создание заявки, комментарии, смена статуса сотрудником, журнал статусов.
- Статистика количества заявок по статусам для сотрудников.
- CSRF-защита HTML-форм и параметризованные SQL-запросы.
- SQL-схема из 10 таблиц и заполнение справочников.

## ML: текущий статус
По умолчанию **модель не обучена**: заявки получают категорию `Other`, фиктивная уверенность не записывается. Чтобы обучить прототип, создайте `data/tickets.csv` с заголовками `text,category` и размеченными обращениями (Network, Hardware, Software, Account, Other), затем выполните `python train_ml.py`. Программа сохранит `models/ticket_classifier.joblib`. Для реальной эксплуатации нужны качественный датасет, разделение train/test, оценка F1 и контроль ошибок. Не загружайте недоверенные joblib-файлы.

## Как сделать сотрудника поддержки
После регистрации пользователя назначьте роль вручную в локальной БД (не через публичный интерфейс):

```sql
UPDATE users SET role_id=(SELECT role_id FROM roles WHERE name='SUPPORT') WHERE email='support@example.com';
```

Замените адрес на email зарегистрированного сотрудника. Аналогично можно назначить `ADMIN`.

## Структура
- `app/__init__.py` — Flask-маршруты и работа с PostgreSQL
- `app/ml.py` — подключение обученной модели или безопасный fallback
- `app/templates/` — HTML-страницы
- `app/static/` — CSS
- `database/schema.sql` — создание таблиц
- `database/seed.sql` — справочники
- `database/test_database/` — учебные данные и 20 запросов для DBeaver
- `train_ml.py` — обучение прототипа ML
- `tests/` — базовые тесты

## Ограничения MVP
Это учебный прототип, не production: пока нет загрузки вложений, назначения исполнителя, пагинации, миграций, восстановления пароля, полноценной аналитики, rate limiting и production-настроек деплоя. Не размещайте приложение в открытом интернете без дополнительной защиты. Файл `.env` и реальные персональные данные нельзя коммитить.
